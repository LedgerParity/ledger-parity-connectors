# SDP 7.0.0 payment CSV

The `sdp.Parse` adapter maps the payment CSV contract at release **7.0.0**, revision `14704274467d267b6c6679052d7251ef6050d118`. This is a release-scoped file adapter, not an authenticated SDP API client or a partnership claim. Tests use synthetic exports; no deployed SDP installation was exercised.

Inspected sources: [export handler](https://github.com/stellar/stellar-disbursement-platform-backend/blob/14704274467d267b6c6679052d7251ef6050d118/internal/serve/httphandler/export_handler.go), [upstream header assertions](https://github.com/stellar/stellar-disbursement-platform-backend/blob/14704274467d267b6c6679052d7251ef6050d118/internal/serve/httphandler/export_handler_test.go), [native asset semantics](https://github.com/stellar/stellar-disbursement-platform-backend/blob/14704274467d267b6c6679052d7251ef6050d118/internal/data/assets.go). Read source, not executed upstream tests.

Caller supplies the exact network, deployment/source name and `sdp.Scope`: release, independently known sender, closed settlement interval and an assertion describing how scope was established. Source means a stable deployment/export origin, not a filename. Split mixed-sender exports before import using independent application information; never infer expected sender or interval from the chain payment under test.

The strict header set matches the inspected export, with reordering permitted. ID becomes the source record ID, StellarTransactionID the chain reference, ExternalPaymentID a separate business reference. Amount stays exact. XLM/NATIVE with empty issuer normalizes to native XLM; issued assets retain case-sensitive issuer identity. Duplicate rows are preserved for the engine to classify. Creation/update times validate but are not reused as settlement times. Contact fields are discarded. Empty destination, unknown statuses/types, invalid amounts, successful records without a transaction reference and Circle routes fail the whole import; unregistered receivers require a separate workflow rather than fabricated destinations.

Exports can be restricted by selected accounts, filters and caller visibility. The adapter never establishes completeness, and the CLI rejects `target_app.complete=true` for sdp-csv. Unclaimed observations remain UNKNOWN. Records sharing a transaction hash can still be ambiguous; no operation ID is invented. A declared expected settlement interval is an operator assertion, not source-certified payment execution time.

The CLI [SDP workflow](https://github.com/LedgerParity/ledger-parity-cli/blob/main/docs/SDP_EVIDENCE.md) provides a complete offline example, evidence capture and replay commands. Before expanding compatibility, test another pinned release/export and obtain an independently produced sanitized operator case.
